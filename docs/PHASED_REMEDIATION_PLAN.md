## 1. Executive summary

The platform has already completed the hard architectural work:

- pnpm workspace and Turborepo orchestration with `workspace:*` package links.
- Shared contracts, API transport, and design-system packages.
- Host-mediated event bus (ADR-003), host-owned SSE transport (ADR-004), workflow terminal signals (ADR-005), slot bridge registry (ADR-006), and declaration-driven slot contributions (ADR-007).
- Slot validation race and fail-open behavior are largely addressed by ADR-006/ADR-007 and existing tests.
- 68 test files across remotes and packages; root CI runs typecheck, test, and build.

The remaining risk is **ownership and wiring**, not greenfield architecture. Three issues prevent calling the platform healthy:

1. **The shell imports remote implementation modules and reaches into generated `compiled-types`** (`grab_seller_auth/AuthService`, `grab_seller_auth/compiled-types/...`, `grab_seller_account/Service`). This couples the shell to remote internals and violates the boundary rules in `Current_System_Architecture.md`. Generated `@mf-types` for UI entrypoints is acceptable; importing the remote's service/feature implementation is not.
2. **Session refresh does not refresh tokens**, and the session snapshot drops `roles`, `permissions`, `name`, and `avatar`. Expired sessions log users out instead of rotating cookies, and authorization data is always empty.
3. **SSE and workflow handling only exist on product routes**, because `useSseStream` is mounted from `CatalogRemote`. Onboarding also never emits its success event, so the host cannot navigate after registration.

This plan fixes those issues in eight phases. Phases 0–2 restore guardrails, boundaries, and session correctness. Phases 3–5 complete host ownership and user-facing flows. Phases 6–7 harden the transport, types, tooling, docs, and deployment path.

## 2. Scope, assumptions, and non-goals

### 2.1 In scope

- `apps/grab-seller` (host/shell)
- `apps/grab-seller-auth`
- `apps/grab-seller-account`
- `apps/grab-seller-product`
- `apps/grab-seller-inventory`
- `apps/grab-seller-pricing`
- `packages/seller-contracts`
- `packages/seller-api`
- `packages/seller-ui`
- Root tooling: pnpm, Turborepo, ESLint, Prettier, Vitest, GitHub Actions
- Docker, nginx, compose, and standalone remote bootstraps
- `docs/` and ADR updates

### 2.2 Assumptions

- Credentials remain server-managed in `HttpOnly` cookies; no tokens are stored in JavaScript or exposed through contracts/events.
- The backend can expose (or already exposes) `roles`, `permissions`, `name`, and `avatar` on the identity profile endpoint. If not, a backend ticket is a hard dependency for the authorization portion of Phase 2.
- `SellerPlatform` remains the single integration surface for remotes.
- The host event bus remains page-session durable; REST/HATEOAS remains the source of truth for business data.
- The slot bridge and declaration-driven slot contributions are already implemented and are not redesigned here.
- Shell and remotes are deployed as separate containers but built from the same workspace lockfile.
- One shell instance owns one browser page session.

### 2.3 Non-goals

- Redesigning the visual language or component library.
- Replacing React, Vite, Module Federation, TanStack Query, or the HATEOAS backend.
- Adding a global Redux/Zustand store across MFEs.
- Per-MFE SSE connections or remotes importing `createBackendEventStream`.
- Moving authorization decisions to the frontend; the backend remains authoritative.
- Backend workflow/outbox changes beyond the contract fields needed by the UI.
- Migrating to a different bundler or monorepo tool.

### 4.3 Session contract (target)

```ts
export type SessionExpiredReason = "refresh-failed" | "unauthorized" | "logout" | "manual";

export interface SessionApi {
  /** Current snapshot — never throws. */
  getSnapshot(): SessionSnapshot;

  /** Subscribe to state transitions. Returns an unsubscribe function. */
  subscribe(listener: (snapshot: SessionSnapshot) => void): () => void;

  /**
   * Rotate the session cookie and re-read the profile.
   * Shell-coordinated with a mutex; concurrent calls share one in-flight refresh.
   */
  refresh(): Promise<void>;

  /**
   * Host-only transition to anonymous. Called by the API client when a 401
   * cannot be recovered, by logout, or by an explicit user action.
   */
  expire(reason?: SessionExpiredReason): void;

  /** Sign out and transition to anonymous. */
  logout(): Promise<void>;
}
```

Rules:

- `getSnapshot()` is the single source of truth; auth events remain signal-only (`{}` payloads).
- `refresh()` = `POST refresh` (cookie rotation) **then** `GET profile` (new snapshot). It must not call `getProfile()` alone.
- `expire()` is idempotent: if already anonymous, it does not re-emit or re-navigate.
- React consumers use `useSessionSnapshot()` from `seller-ui` (backed by `useSyncExternalStore`), not render-time `getSnapshot()`.
- Transient network errors during bootstrap do not transition to `anonymous`; they keep the current state and retry with backoff. Only 401/403 transition to anonymous.

### 4.4 SSE and workflow contract (target)

- The shell opens **exactly one** authenticated `fetch` + `ReadableStream` connection.
- It starts when `SessionSnapshot.status === "authenticated"`.
- It aborts on logout, anonymous state, unmount, or access-context change.
- It restarts after `auth:context-selected:v1` so scoped server publishes match the new context.
- Remotes never import `createBackendEventStream`; they subscribe to `platform.events`.
- Stream lifecycle topics remain signals: `stream:ready:v1`, `stream:disconnected:v1`.
- The host maps the named SSE event `workflow` onto `workflow:updated:v1`:
  `{ producerId, workflowId, workflowName, status, idempotencyKey?, errorMessage? }`.
- `useWorkflowAwaiter` subscribes **before** the POST, buffers one matching terminal frame, and matches on `workflowName` + `idempotencyKey` (ADR-005).
- Heartbeat comments (`: ping`) never reach `platform.events`.

### 4.5 Slot and event invariants

- ADR-003: `emit` for signals/RPC, `setState` for entity state with last-value replay.
- ADR-006/007: declaration-driven slot contributions and capability registry remain as implemented.
- Slot change emitters must cancel pending debounce work on unmount.
- Domain state is cleared on route/form unmount via `events.clear(scope)`.

### 4.6 Definition of a healthy boundary

A boundary is healthy when:

1. The shell can build and typecheck without any remote source on disk, using generated `@mf-types` produced by `pnpm mf:types` from the remote builds/manifests. `MF_DTS=0` only skips the dts plugin; it does not remove the need for generated `@mf-types`, because `apps/grab-seller/tsconfig.app.json` maps `grab_seller_*` to `@mf-types/*` and includes `@mf-types`.
2. The shell imports only remote UI entrypoints listed above.
3. Remotes can build and render standalone without importing shell internals.
4. Shared packages never import `apps/*`.
5. A new violation fails CI, not code review memory.

**MF type pipeline:**

```text
remote source ──(MF_DTS=1 build)──▶ apps/<remote>/@mf-types/{*.d.ts, compiled-types/}
                                            │
                                            ▼ serve @mf-types.d.ts + @mf-types.zip
shell type consumer (MF_DTS=1) ──▶ apps/grab-seller/@mf-types/<remote>/*.d.ts
                                            │
                                            ▼
                                 tsc -b (shell typecheck / build)
```

`MF_DTS=0` disables the dts plugin during a build, but the shell's `tsc -b` still resolves every `grab_seller_*` import through `@mf-types`. Generated declarations are therefore a build prerequisite, not optional metadata. The shell must not import remote implementation modules or `compiled-types` directly; it may consume the generated UI entrypoint declarations.

### 9.2 Implementation steps

1. **Extend the session contract.**

   ```ts
   export type SessionExpiredReason = "refresh-failed" | "unauthorized" | "logout" | "manual";

   export interface SessionApi {
     getSnapshot(): SessionSnapshot;
     subscribe(listener: (snapshot: SessionSnapshot) => void): () => void;
     refresh(): Promise<void>;
     expire(reason?: SessionExpiredReason): void;
     logout(): Promise<void>;
   }
   ```
   - Add `expire` to every implementation: shell session facade, standalone platform, test mocks.
   - Keep `SessionSnapshot` as the three-state union. Do not add token fields.

2. **Fix the API client 401 flow and concurrency races.**
   - Change `ApiClientConfig.platform` to:
     ```ts
     platform?: {
       session: {
         refresh(): Promise<void>;
         expire(reason?: SessionExpiredReason): void;
       };
     };
     ```
   - Coordinate concurrent 401s via `RefreshCoordinator` and track `lastRefreshedAt: number`:
     1. If a 401 arrives for a request that was initiated _before_ `lastRefreshedAt` (meaning an in-flight request was dispatched with an expired token while a concurrent refresh was already completing), do **not** trigger a second refresh; retry the request once immediately with the fresh session cookie.
     2. If the request was initiated _after_ `lastRefreshedAt`, call `platform.session.refresh()`. Concurrent callers join the single in-flight refresh promise.
     3. If refresh throws:
        - If the error is an `ApiError` with `401`/`403`, call `expire("refresh-failed")`.
        - If it is a network/timeout error, do **not** expire; rethrow so the caller/UI can retry.
     4. Retry the request once with fresh credentials.
     5. If the retry returns `401`, call `expire("unauthorized")` and return the error.
   - Never retry the refresh call itself through the 401 interceptor.
   - Add a `refreshTimeoutMs` (default 15 s) and an overall request `timeoutMs` (default 30 s) in Phase 6; for Phase 2, at least ensure a rejected refresh is handled.

3. **Parse JSON and HAL responses.**
   - `readResponse` should:
     - Return `undefined` for `204` or empty bodies.
     - Parse `application/json`, `application/hal+json`, `application/problem+json`, and `text/plain`.
     - Throw `ApiError` with `status`, `statusText`, and parsed body for non-OK responses.
     - Fall back to text when JSON parsing fails.
   - Add tests for `application/json` login/register responses.

4. **Fix `refresh()` and `loadSession()`.**
   - `refresh()`:
     ```ts
     await identityService.refreshToken(); // rotate cookie
     const profile = await identityService.getProfile();
     publishSnapshot(profileToSnapshot(profile));
     events.emit("auth:session-refreshed:v1", {});
     ```
     On failure:
     - 401/403 → `expireSession()` and rethrow.
     - Network/5xx → rethrow **without** expiring; the API client decides whether to expire based on the error type.
   - `loadSession()`:
     - 200 → authenticated snapshot.
     - 401/403 → anonymous.
     - Network/5xx → keep the current snapshot (`loading` on cold start), log, and retry with exponential backoff (e.g., 1 s, 2 s, 4 s, max 30 s). Do not navigate to login on a transient failure.
     - Accept an `AbortSignal` or a `cancelled` flag so unmount/StrictMode does not publish stale state.
   - `expireSession()`:
     - Idempotent: if `snapshotRef.current.status === "anonymous"`, return.
     - Publish anonymous, call `onSessionCleared`, emit `auth:session-expired:v1` once.

5. **Map the full profile.**

   ```ts
   export const profileToSnapshot = (profile: IdentityProfile): SessionSnapshot => {
     const { createdAt: _createdAt, roles, permissions, ...user } = profile;
     return {
       status: "authenticated",
       user,
       roles: roles ?? [],
       permissions: permissions ?? [],
     };
   };
   ```
   - In `createIdentityService.getProfile`, map `name` and `avatar` from the profile response. If the backend omits `name`, fall back to the email local-part; if `avatar` is absent, leave it `undefined`.
   - Confirm with the backend whether `roles`/`permissions` are top-level profile fields or derived from `accessContexts`. If derived, document the mapping and add a test.

6. **Make session consumption reactive.**
   - Add `packages/seller-ui/src/hooks/use-session.ts`:
     ```ts
     export function useSessionSnapshot(): SessionSnapshot {
       const platform = useRequiredPlatform();
       return useSyncExternalStore(
         platform.session.subscribe,
         platform.session.getSnapshot,
         platform.session.getSnapshot,
       );
     }
     ```
   - Add `useRequiredPlatform()` in `seller-ui` (it becomes the standard accessor in Phase 3). If a widget is genuinely platform-optional, use a separate nullable hook rather than silently returning `anonymous`.
   - Export `useSessionSnapshot` and an optional `useAuthState` selector.
   - Replace render-time `platform.session.getSnapshot()` in `UserMenuWidget` and `AccessContextMenu`.
   - Add a lint rule or grep check to prevent new render-time reads outside adapters/tests.

7. **Fix provider/bootstrap races.**
   - `AuthProvider`:
     - Remove the unused `runtimeConfig` prop.
     - Set `sessionRef.current = session` in `useLayoutEffect`, not during render.
     - Guard `platform.api` explicitly; if missing, render a clear error/loading state instead of `platform.api!`.
   - `ShellPlatformProvider`:
     - Create a late-bound `sessionBridge` ref.
     - Pass `refresh` and `expire` to `createApiClient`.
     - Keep the API client stable across renders.
   - `useSessionEffects`:
     - Run bootstrap once (ref guard) and cancel on unmount.
     - Add a `visibilitychange` listener: when the tab becomes visible and the session is authenticated, call `refresh()` (throttled to at most once per 30 s) to satisfy ADR-002 tab revalidation.
     - Do not redirect while `status === "loading"`.
     - On `auth:context-selected:v1`: call `onSessionCleared?.()` (which invokes `queryClient.clear()` in the shell) and `events.clear()` for domain scopes to prevent stale merchant cache leakage across context switches, before reloading session and reconnecting SSE.

8. **Remove timer-based auth callbacks.**
   - In `login-form.tsx` and `register-form.tsx`, call `onLoginSuccess`/`onRegisterSuccess` immediately after a successful mutation.
   - If a success animation is desired, use CSS transition or `onAnimationEnd`; never delay a navigation callback with `setTimeout`.
   - In `access-context-selection-view.tsx`, clear the timer on unmount or navigate immediately after success.

## Appendix B — Sequence diagrams

### B.1 Session bootstrap and 401 refresh

```text
Cold start
  Shell: snapshot = loading
  Shell -> API: GET /identity/profile (credentials: include)
    ├─ 200 -> snapshot = authenticated(user, roles, permissions)
    ├─ 401/403 -> snapshot = anonymous -> redirect /login
    └─ network/5xx -> keep loading -> retry with backoff

Business request
  Remote -> API: GET /resource (credentials: include)
    ├─ 200 -> data
    └─ 401 -> API client -> platform.session.refresh()
         Shell -> API: POST /identity/auth/refresh
           ├─ 200 -> Shell -> API: GET /identity/profile
           │         -> snapshot = authenticated
           │         -> API client retries original request once
           └─ 401/403 -> platform.session.expire("refresh-failed")
                         -> snapshot = anonymous -> redirect /login
```

### B.2 Host-owned SSE lifecycle

```text
Login / cold start
  AuthProvider: snapshot = authenticated
  EventStreamProvider: enabled = true
    -> resolve stream URL (config > HAL > fallback)
    -> fetch(url, { credentials: include, Accept: text/event-stream })
    -> on "ready": events.emit("stream:ready:v1", { producerId, lastEventId })
    -> on "workflow": events.emit("workflow:updated:v1", payload)

Route change
  CatalogRemote unmounts -> no stream effect cleanup (provider is above routes)
  Inventory route mounts -> same connection

Logout
  snapshot = anonymous
  EventStreamProvider cleanup -> abort()
    -> events.emit("stream:disconnected:v1", { reason: "logout" })

Context change
  events.emit("auth:context-selected:v1")
    -> AuthProvider reloads session
    -> EventStreamProvider deps change (scopeId)
    -> abort old stream -> start new stream
```

### B.3 Onboarding submit

```text
User submits application
  AccountOnboardingSubmit -> POST submit link
    ├─ success -> useOnboardingFlow.onSubmitSuccess()
    │              -> refetch application
    │              -> platform.session.refresh() (pulls new merchant accessContext)
    │              -> events.emit("seller-merchant:registration-success:v1", {})
    │              -> onSuccess?.()
    │              -> host listener navigates home (with non-empty accessContext, preventing bounce)
    └─ failure -> toast(error.message); stay on review step
```
